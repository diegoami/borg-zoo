# What a seed does, and what this comparison has not established

We can pass the same integer seed to C and Neo. The earlier statement that there is no way to carry seeds between them was too absolute. The current harnesses have not established that the same integer describes the same starting experiment. A seed starts a random stream; it is not a portable serialized character, dungeon, knowledge state or Borg memory.

## Concrete differences checked in code and records

1. **Different birth procedures.** Native measurement code describes ordinary UI/default point buy ([native-run.py:83–85](https://github.com/diegoami/borg-zoo/blob/7ae123b8240e92428470e9c2b6145eebc9ef614b/toolkit/native/native-run.py#L83)); the historical report explicitly records the C/Neo difference ([maintainer handoff](https://github.com/diegoami/borg-zoo/blob/e24de5b/reports/originals-20261108-classes-1800/42534228784-1/MAINTAINER-HANDOFF.md)). The Neo host passes seed/race/class/depth, with no point-buy allocation ([session.ts:44–51](https://github.com/diegoami/neo-angband-borg-mod-tracker/blob/9c17cb0c582fe129008899491372787e91abdade/tools/zoo/session.ts#L44)). Engine [game.ts:3642–3648](https://github.com/neostryder/neo-angband/blob/06a2321ce30a414df20d1b20d486446e7688171c/packages/core/src/session/game.ts#L3642) uses point buy only with `roller=point` and a full birthStats array; otherwise it rolls. Different stats and draw counts change both initial strength and subsequent dungeon generation.
2. **Different recorded birth options.** The C619-death baseline's [summary](https://github.com/diegoami/borg-zoo/blob/e24de5b/reports/originals-20261108-classes-1800/42534228784-1/summary.json) records birth_no_selling=1 for all1,800 C lives. Current Neo [pinned cells](https://github.com/diegoami/borg-zoo/blob/458395d628b9ab2982d77a4f53a823f5d606d286/results/neo-fork-9c17cb0-events-classes-1800/43617859717-1/cells.jsonl) record false for1,799 lives and no options record for the timeout. This changes shop/economy conditions; it is not evidence of how much of the death gap it explains. Native birth stats/gear were not comprehensively recorded, so equal birth state cannot be reconstructed from those summaries alone.
3. **Different Borg startup RNG.** C [borg-init.c:512–514](https://github.com/angband/angband/blob/e473720ed88a0f0c7ca66815cef3000eb4a38bc3/src/borg/borg-init.c#L512) draws its private startup seed with randint1(0x10000000) from the game RNG. TS [rng.ts:62–73](https://github.com/diegoami/neo-angband-borg-mod-tracker/blob/9c17cb0c582fe129008899491372787e91abdade/src/rng.ts#L62) defaults to0x00c0ffee; [plugin.ts:220](https://github.com/diegoami/neo-angband-borg-mod-tracker/blob/9c17cb0c582fe129008899491372787e91abdade/plugin.ts#L220) does not supply rngSeed. Thus a shared game seed does not automatically align either Borg-local rolls or the game stream's position at Borg activation. This is a checked difference, not a measured share of mortality.
4. **Startup position matters.** Core [game.ts:3618–3633](https://github.com/neostryder/neo-angband/blob/06a2321ce30a414df20d1b20d486446e7688171c/packages/core/src/session/game.ts#L3618) supports continuation RNG state and records the accepted birth RNG position; birth/menu/history, store generation, flavor seeds and level generation consume the stream. An extra draw shifts subsequent draws. The RNG family itself is not a reason to declare matching impossible: C z-rand.c and the port rng.ts implement the related WELL/quick generators. This investigation did not prove a defect in their raw generator arithmetic.
5. **Observation and actions matter after birth.** Host message/view plumbing and known versus actual state are part of the experiment. Different decisions consume different combat and movement draws and diverge worlds. Once different Borgs make different choices, identical later trajectories are not expected even from a verified common initial state. A comparison should locate the first unexpected divergence, rather than demand identical play forever.

## Three useful forms of comparison

| Question | Suitable experiment | What the seed means |
|---|---|---|
| Did a Neo change help or regress? | Same engine/content/host/birth profile, baseline versus candidate, frozen suite in one run | Pair by seed after checking equal accepted starting conditions; divergent decisions thereafter are expected |
| Is Neo's survival distribution close to C's? | Sufficient, prespecified cohorts with the same race/class allocation, birth policy, effective options, caps and host validity; stratified report | Seed is a reproducibility ID within each engine; unpaired comparison is valid without identical generated worlds |
| Does this TS decision reproduce C? | Identical controlled scenario translated to each engine, matching player, items, terrain, monsters, knowledge, timers and RNG inputs | Compare one decision or bounded sequence; numeric seed alone is inadequate |

Cross-engine paired worlds are an achievable engineering target, not an existing feature. First log full actual birth and both RNG states, align one birth profile and startup procedure, and compare normalized checkpoints: accepted birth, first town, first dungeon, first Borg decision. At the first difference inspect semantic state and draw counts. Record raw hashes and normalized semantic fingerprints separately: C and TS serialization/handles need not be byte-identical. Do not advertise portable C/Neo save interchange without implementing and verifying it.

For death debugging, portable small scenarios are likely the quickest route: same low-HP player, same immobile monster and stairs, same knowledge/visibility, same danger inputs, and a C decision oracle. Replay the original within each engine separately. This complements cohort statistics; neither replaces the other.

The survival gap is unresolved. Historical C619/1,800=34.39% versus corrected Neo1,352/1,800=75.11% is alarming descriptive evidence, not a controlled effect estimate. Birth/options mismatch can confound it, but no calculation here attributes the gap to those mismatches. Known engine and port failures remain real. CI reporting should make this distinction explicit and help remove the confounders.
